# Minimal Steiner Tree

Консольная утилита для построения деревьев Штейнера для многотерминальных сетей. 
Входные примеры находятся в папке [input](input/), а автоматическая проверка результата выполняется через [pipeline.py](pipeline.py) и [validator/validator.py](validator/validator.py).

## Текущее состояние

Python-пайплайн и валидатор готовы. На данном этапе валидатор использует только поле `nets` из входного JSON:

- каждая входная сеть должна присутствовать в выходном файле ровно один раз;
- для каждой сети все её терминалы должны быть соединены рёбрами из `edges`;
- `net_id` выходной сети должен совпадать с `net_id` входной сети.

На этом этапе препятствия, слои и `steiner_params` не проверяются.

## Требования

1. Python 3.14 или новее.
2. CMake версии 3.15 или выше.
3. Компилятор C++ с поддержкой C++17.
4. Для GUI требуются `PyQt6`, `matplotlib` и `PyInstaller`.

При первом запуске `pipeline.py --gui` пайплайн создаёт `.venv` и автоматически устанавливает эти зависимости. Для этого необходим доступ к PyPI.

## Сборка

Цель `SteinerTree` создаёт консольную программу `SteinerTree.exe` в корне проекта.

Цель `SteinerTreeGUI` собирает автономный GUI в папку `SteinerTreeGUI/`. Главный файл приложения — `SteinerTreeGUI/SteinerTreeGUI.exe`; рядом с ним располагается необходимый `SteinerTree.exe` и папка `input/`.

`SteinerTreeGUI` не включена в цель `ALL`: обычная сборка C++ не тратит время на упаковку Python-приложения. Соберите её явно из CMake или запустите GUI через пайплайн — он сам настроит CMake и соберёт эту цель, если исполняемый файл ещё отсутствует.

## Контракт C++-программы

Пайплайн вызывает C++-программу в следующем формате:

```text
SteinerTree.exe <входной_json> <выходной_json>
```

Например:

```powershell
.\SteinerTree.exe input\test.json output\result.json
```

C++-часть должна:

1. Проверять, что передано ровно два аргумента после имени программы.
2. Читать входной JSON из `argv[1]`.
3. Обработать **каждый** объект из входного массива `nets`.
4. Записать выходной JSON по пути из `argv[2]`.
5. При ошибке чтения, построения или записи сообщать о ней в `stderr` и завершаться с **ненулевым** кодом.

**Пайплайн не сможет подтвердить результат, если C++-программа не создаёт выходной файл.**

## Формат результата

Допускается корневой объект с массивом `nets` или сам массив сетей. Рекомендуемый формат:

```json
{
  "nets": [
    {
      "net_id": "N1",
      "edges": [
        {
          "from": {"x": 5, "y": 5},
          "to": {"x": 20, "y": 5}
        },
        {
          "from": {"x": 20, "y": 5},
          "to": {"x": 40, "y": 10}
        }
      ]
    }
  ]
}
```

Для каждого `net_id` из входного `nets` нужен один объект результата. Каждое ребро содержит `from` и `to` с числовыми координатами `x` и `y`. Терминалы одной сети могут соединяться через точки Штейнера, но все исходные терминалы сети должны находиться в одной связной компоненте рёбер.

## Запуск

### Графический интерфейс

```powershell
.\.venv\Scripts\python.exe pipeline.py --gui
```

Команда не принимает входные или выходные файлы. Если `SteinerTreeGUI/SteinerTreeGUI.exe` отсутствует, пайплайн создаёт `.venv` (при необходимости), устанавливает зависимости GUI, настраивает CMake, собирает цель `SteinerTreeGUI` и открывает приложение.

### Консольный пайплайн

```powershell
.\.venv\Scripts\python.exe pipeline.py input\test.json output\result.json
```

При первом запуске пайплайн автоматически настроит CMake и соберёт `SteinerTree.exe`. Аргументы задаются повторяющимися парами:

```text
<входной_json> <выходной_json>
```

Несколько запусков за одну команду:

```powershell
.\.venv\Scripts\python.exe pipeline.py input\test.json output\mst.json input\test.json output\result.json
```

Пайплайн создаёт родительскую папку для выходного файла, запускает C++-программу и затем проверяет структуру JSON, набор сетей и связность терминалов.
